## 目标与范围

实测当前账号已开通的中国区内部测试能力。使用 boto3 直接调用中国区
AgentCore API，保留请求参数、会话标识、响应、错误和耗时，产出可重复执行的测试代码及中文报告。
凭证由本地 AWS profile 加载，不写入代码、日志或报告。

| 编号 | 优先级 | 方法 | 通过标准 |
| --- | --- | --- | --- |

无法直接证明服务内部使用了全新或预热的 microVM。每档先执行一批；如出现失败，保留首轮结果，
仅针对具体原因补充诊断或复测。

## 执行顺序

1. **准备与接口探测**：确认账号、区域和 SDK 版本，读取 API 参数模型；尝试默认
   `aws.codeinterpreter.v1` 的创建、执行、停止。若默认资源不可用，检查资源清单和错误，
   根据实测选择可用资源；需要新建自定义资源时在报告记录配置和清理结果。
2. **实现测试程序**：统一处理事件流、错误、测时、证据落盘和会话清理；
   SDK 自动重试策略写入结果，避免重试掩盖并发首轮错误。
3. **基础功能**：依次验证 2.1、2.2、2.3、2.4、2.5、2.9。
4. **依赖与超时**：验证 2.10 和 2.6，尤其检查超时后代码是否继续运行。
5. **并发新会话**：依次执行 1、10、50 并发；每档完成后清理会话，再进入下一档。
6. **汇总与清理确认**：生成项目结论及并发统计，确认测试会话均已停止，
   删除本次测试创建的临时资源和本地宿主标记文件。

## 结果分类

- **PASS**：实测证据满足对应标准。
- **FAIL**：调用或结果明确违反标准；保留错误码、request ID 和原始证据。
- **BLOCKED**：权限、配额、接口配置或环境前置条件阻止测试，说明具体原因；
  不将未执行的测试标记为通过。
- **PARTIAL**：仅部分子项得到验证，明确缺失项。

并发首次失败与诊断后复测分别记录。所有时间使用 UTC；耗时用单调时钟计算。
测试可能产生 Code Interpreter 使用费用；会话设置有限有效期，并在 `finally` 中停止，
另外保留资源台账供中断后清理。仅清理本次创建的资源，不修改账号其他配置。
